# Lumina 校园即时通讯平台设计

日期：2026-10-30  
状态：已确认并完成实施

## 1. 目标与边界

Lumina 解决高中教师与教室之间依赖线下找人的沟通问题。平台以“班级 + 科目 + 教师”为普通通道，以全校、年级或班级范围为广播通道，服务管理员、教师和教室三种角色。

交付范围包含 Next.js 三端、Go 独立后端、PostgreSQL 持久化、Redis 在线状态与 Pub/Sub、JWT 双令牌认证、文件传输、自动化测试、数据库迁移、种子数据、Docker Compose 与部署文档。业务数据仅保存在服务端；浏览器存储仅用于必要的认证会话和界面偏好，不保存消息、通道或公告副本。

## 2. 仓库与运行架构

采用 Monorepo：

- `apps/web`：Next.js 15 App Router、React 19、TypeScript、Tailwind CSS、shadcn/ui、TanStack Query、Zustand。
- `apps/api`：Go、Gin、GORM、gorilla/websocket，按配置、数据库、鉴权、领域服务、HTTP 处理器和 WebSocket Hub 分层。
- `apps/api/migrations`：按顺序执行的 PostgreSQL 迁移。
- `apps/api/seed`：可重复执行的演示与验收种子数据。
- `tests/e2e`：Playwright 跨角色、跨浏览器场景。
- `deploy`：Docker Compose、环境变量样例、反向代理与初始化配置。
- `docs`：架构、API、测试和部署文档。

浏览器通过同源反向代理访问 `/api` 与 `/ws`。Next.js 只承担界面和前端状态，不伪造业务 API。Go 是唯一业务写入入口；PostgreSQL 是唯一持久化事实来源；Redis 只承载限流、短期认证状态、在线状态和实时广播。

## 3. 身份与权限

统一登录接收用户名和密码，使用 bcrypt 校验。成功时签发 24 小时 Access Token 和 7 天 Refresh Token，并按角色跳转 `/admin`、`/teacher` 或 `/classroom`。刷新令牌采用随机高熵值，数据库只保存其哈希；刷新时旋转并废止旧令牌，重复提交已使用令牌时废止该令牌族。

教室设备绑定码是一次性或可轮换的高熵凭据，兑换标准双令牌会话，不绕过角色和通道鉴权。登录失败按“账号 + 来源地址”在 Redis 计数，连续五次失败锁定十五分钟。认证、刷新、登录和上传接口分别限流。

每个受保护请求执行 Access Token 验证、用户有效状态检查和角色检查。通道读取、发送、搜索、回执、撤回等操作额外查询通道成员关系；教师只能访问本人教学任务或授权广播通道，教室只能访问本班通道，管理员能力通过独立管理接口暴露。前端隐藏入口不能替代服务端鉴权。

## 4. 数据模型与一致性

核心表为用户、班级、科目、教学任务、通道、消息、已读回执、公告、审计日志，并增加刷新令牌、设备绑定、公告确认和通道已读位置等支撑表。

关键约束：

- 用户名唯一；教学任务 `(teacher_id, class_id, subject_id)` 唯一。
- 普通通道 `(class_id, subject_id, teacher_id)` 唯一；广播通道使用专用范围字段和类型约束。
- 消息使用 BIGSERIAL 主键，按 `(channel_id, id)` 排序和游标分页，避免时间相同导致乱序。
- 已读回执 `(message_id, user_id)` 唯一；公告确认 `(announcement_id, user_id)` 唯一。
- 撤回、删除采用服务端状态或软删除；外键、非空、长度及枚举约束在数据库和领域层共同校验。

教学任务创建与通道生成位于同一数据库事务。批量通知逐通道持久化并记录每个目标的结果，任一数据库错误不制造虚假成功；接口返回逐项目状态。消息写库成功后才发布 Redis 事件，防止在线用户收到无法持久化的消息。

## 5. API 与实时事件

REST API 按 `/api/v1` 分组：认证、仪表盘、班级、教师、科目、教学任务、通道、消息、公告、上传和审计日志。列表采用明确分页；历史消息采用 `before_id + limit` 游标。上传先校验声明大小、实际大小、扩展名和 MIME，再以服务端生成的随机对象名存储，下载重新鉴权并设置安全响应头。

WebSocket 地址为 `/ws?access_token=...` 或通过受保护子协议传递短期凭据，服务端复用同一认证与通道授权逻辑。Hub 以用户和通道维护连接集合，连接读超时配合 30 秒心跳；写操作串行化，慢连接有界排队并安全关闭。前端断线后指数退避重连并带随机抖动，重连成功重新同步会话、未读数和最新消息，不依赖轮询维持在线。

事件信封包含 `event_id`、`type`、`channel_id`、`occurred_at` 和 `data`。事件类型为 `new_message`、`message_edited`、`message_deleted`、`announcement`、`typing`、`presence`、`read_ack`。客户端按事件 ID 去重，以消息 ID 排序。Redis Pub/Sub 用于实例间分发；断线期间的消息不依赖 Redis 补偿，而由重连后的数据库同步补齐。

## 6. 消息与公告流程

发送消息时，服务端验证角色、通道成员、消息类型、正文长度和回复目标，写入 PostgreSQL，再发布事件。文本最多 2000 字，图片最大 5 MiB，文件最大 20 MiB。React 仅按纯文本渲染消息，不注入 HTML；SQL 使用参数化查询；基于 Bearer Token 的接口不依赖 Cookie，从而避免传统 CSRF 写入路径。

撤回仅允许发送者在两分钟内操作，以服务端时间判定。已读回执自动上报且幂等，未读数由服务端计算并通过事件更新。搜索限定在调用者有权访问的通道内。

普通通知使用黄色视觉层级；紧急通知使用红色层级并要求确认。教室端收到未确认的紧急消息或公告后展示阻断式全屏对话框，播放经用户交互解锁的提示音，只有确认接口成功后才允许关闭。刷新或重连时从服务端重新获取未确认项，不能通过关闭页面规避。

## 7. 前端结构与体验

- 登录页：统一入口、明确错误与锁定反馈，不暴露账号是否存在。
- 管理端：深色侧栏、概览指标、资源数据表、教学任务分配、公告发布和审计日志；变更成功后刷新服务端查询缓存。
- 教师端：会话列表与聊天窗口双栏布局，支持通知、紧急、图片、文件、回复、撤回、搜索和批量通知；窄屏切换为会话/聊天单栏。
- 教室端：1920×1080 优先的大屏科目卡片网格，聊天正文不小于 18px，主要触控目标不小于 48px，并提供公告栏和紧急确认界面。

主色使用需求指定的 Indigo `#6366f1`，Violet 和 Cyan 仅作辅助状态或品牌细节，不使用霓虹光效。所有异步视图提供骨架加载、空状态、错误状态与重试操作。TanStack Query 管理服务端数据，Zustand 只管理当前会话、WebSocket 状态和短期界面状态。

## 8. 错误处理与可观测性

API 使用统一错误结构，包含稳定错误码、用户可读信息和请求 ID，不泄露堆栈或数据库细节。前端区分认证过期、权限不足、限流、网络断开和校验失败。Access Token 刷新采用单飞机制，避免并行请求重复刷新。

Go 中间件记录请求 ID、耗时、状态码和脱敏用户上下文；登录、权限变更、资源管理、公告、撤回等写入审计日志。健康检查区分存活与就绪，就绪检查覆盖 PostgreSQL 和 Redis。

## 9. 测试与验收

- Go：领域规则、权限矩阵、令牌旋转、限流、游标分页、撤回时限、Hub 广播和消息持久化测试；集成测试使用真实 PostgreSQL/Redis。
- Vitest：前端格式化、鉴权跳转、状态归约、WebSocket 去重与重连逻辑测试。
- Playwright：三端登录、越权拒绝、教学任务自动建通道、双窗口实时消息、刷新持久化、未读与回执、紧急确认、批量通知、文件上传下载和断线恢复。
- 并发验证：多连接同时发送后，各通道消息 ID 严格有序、数量一致、无重复丢失。

构建验收包含前端类型检查与生产构建、Go 格式化/静态检查/测试、迁移从头执行、种子重复执行以及 Docker Compose 健康检查。

## 10. 实施顺序

1. 初始化 Monorepo、配置、迁移、种子和健康检查。
2. 完成认证、刷新、限流、RBAC 与三端受保护布局。
3. 完成管理资源 CRUD、教学任务分配和事务性自动建通道。
4. 完成消息持久化、WebSocket Hub、Redis 分发、回执、撤回和重连同步。
5. 完成教师端搜索与批量通知、教室端大屏与紧急确认。
6. 完成公告、图片/文件上传下载和审计能力。
7. 完成响应式、测试、并发验证、容器构建和部署文档。

每个阶段以可启动、可测试为完成条件，不用静态假数据或占位接口替代业务实现。
